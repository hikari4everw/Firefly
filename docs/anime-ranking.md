# 追番排行使用说明

在 Firefly 目录运行 `pnpm dev --host 127.0.0.1`，打开 `/anime/`。页面底部是本机编辑工作台；正式网站只有公开结果。

1. 选择年份及 1、4、7、10 月，点击「创建／打开季度」。
2. 点击「导入当季番剧」，首播日期位于该季度的动画进入待选区。可移出不看的作品，也可粘贴 Bangumi 条目链接补充跨季作品。再次导入仅添加新条目，已有排序保持不变。
3. 追番计划使用必追、想追、观望；观看评价使用神作、佳作、还行、及格、差。切换模式会保留作品清单并把它们放回待选区。
4. 桌面端从右侧待选区拖动封面到档位，拖回待选区可暂时移出排名。同档支持左右排序；点击封面后也能选位置并前后移动。移出作品可用「撤销调整」恢复。
5. 「保存草稿」只保存本机草稿。填写版本名称，再点「保存为公开版本」，生成独立快照。已生成的版本不能被覆盖；从历史版本「复制为草稿」后可继续调整。
6. 在历史版本选择对应版本和点评博客，点击「保存点评关联」。博客可以用该版本的固定链接回链，之后的排行变化不会影响旧文章讨论的版本。

公开数据在 `src/data/anime.json`，随网站正常提交、推送及部署。工作台的保存不自动推送；现有 Obsidian 插件发布单篇文章不会夹带排行数据，因此首次发布排行需按网站代码的正常发布流程提交该 JSON。

草稿位于 `.local/anime/`，被 Git 忽略且不进入 dist；在不同电脑继续工作时需要自行复制这个本机目录。公开仓库可读的 JSON 只应存公开版本。

同目录的多个工作台保存时使用文件写锁，避免互相覆盖。若开发服务在保存过程中异常退出，锁可能残留：关闭该目录所有开发服务后，删除空目录 `.local/anime/.write-lock`，再启动预览即可；不要在仍有工作台保存时清理锁。

季度导入使用站点已有的 Bangumi API 配置。季度按首播日期计算，导入仅保留日本 TV 动画，跨季续播作品通过条目链接补录。接口失败时清单不变，可重试。

部署后访客可切换全部公开季度和版本。没有公开版本时页面显示准备中的空状态。通过 `siteConfig.pages.anime` 或 `PUBLIC_PAGES_ANIME` 控制页面及导航可见性。

旧记录的跨档作品读取时归入上方档位，不改写历史快照文件。季度导入会读取全部分页；不完整结果不会加入清单。

季度导入使用 Bangumi 公共标签「日本」「TV」筛选当季首播电视动画，并检查条目平台为 TV。未标注此标签的作品可通过条目链接补充；再次导入不删除已有作品。

首页默认打开最新已有季度的榜单，本机优先读取该季度草稿；指定历史链接仍显示指定版本。待选区每行四张封面，手机上下排列。
